SNEAKY UNICORN: RAINBOW KITCHEN — v1.0.0
ACTUAL VALIDATION REPORT — 2026-10-03

STATUS
The complete seven-dish game passes the local controller, actual-renderer
integration, native Canvas, asset and package checks described below.
Live browser and physical-device validation remain unverified. These local
checks are not represented as a Safari or iPhone certification.

1. CONTROLLER / DOM SIMULATION — 16 OF 16 PASSED
Runner: Node + jsdom, actual index.html/assets.js/recipes.js/app.js.
Inputs: DOM click, keyboard and synthetic pointer events. No private controller
functions were invoked to skip gameplay. Observations used its read-only
snapshot. Rendering/audio were doubles in this suite; the next suite uses
the actual renderer. Timers and pointer geometry were deterministic.

Passed:
- All seven recipes, every preparation step, correct serve, seven stickers,
  the full-menu celebration and another order cycle.
- A deliberately wrong recipe, friendly wrong-order result, correct pictured
  retry and eventual correct serve. No wrong sticker or order advancement.
- 100 rapid cooking clicks cannot consume multiple recipe steps. Queued serve
  and next-order events cannot duplicate awards.
- Partial-recipe pagehide/reload, reload during a completed-step animation,
  home/continue during that animation, and restarting a fresh tray.
- Earned stickers survive recipe restarts and home/resume.
- Correct-result reload preserves one reward and the next order.
- Wrong-result reload preserves the requested dish and retry path.
- Pointer cancel, ignored second touch, broad drag progress, a single-drag
  step boundary, fresh-touch recovery and blur releasing an active pointer.
- Repeated keyboard events do not add unintended taps.
- Malformed JSON, prototype names, non-string recipe IDs and invalid nested
  order bags recover safely. Valid earned stickers survive normalization.
- Storage read/write permission failures and quota failures allow cooking
  to continue with explicit no-save feedback.
- Mute persistence and gesture-gated simulated audio initialization.
- Recipe/sticker dialog controls and Escape handling.
- Deliberate artwork load failure exposes Retry and recovers when the original
  asset becomes available. No placeholder/replacement art is used.

All 54 mapped production image files were decoded from their real bytes.
No unexpected DOM runtime or captured console errors occurred in these cases.
Evidence: tests/controller-tests.cjs and tests/test-results.json.

Evidence: tests/integration-tests.cjs and tests/integration-results.json.

6. RESPONSIVE / DEVICE / BROWSER LIMITATIONS
The source contains separate portrait and short-landscape layouts, safe-area
padding, dynamic viewport-height fallback, large tool buttons, minimum 44px
small interactive controls, scrollable dialogs, keyboard access and reduced
motion handling. These were structurally reviewed, not measured by a browser
layout engine. Canvas tests at small dimensions do not prove full-page layout.

NOT RUN:
- Live Chromium/Firefox/WebKit/Safari rendering or browser-console inspection.
- Physical iPhone/iPad testing or real touchscreen pointer delivery.
- Visual safe-area/notch/browser-toolbar behaviour on a real device.
- Audible sound, hardware vibration or iOS audio interruption/recovery checks.
- Real service-worker installation, Home Screen launch, cache quota/eviction,
  or an actual browser offline relaunch.

Concrete environment constraints: no browser executable was installed, and
the standard Playwright browser download did not produce a valid archive.
Automatic approval review rejected opening the local game preview in the
cloud browser. That browser action was not retried through another route.
Only the safer local tests above were used after the rejection.

REMAINING REAL-DEVICE ACCEPTANCE CHECK

then verify an offline relaunch after the footer reports offline readiness.
